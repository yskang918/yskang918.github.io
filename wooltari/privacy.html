개인정보 처리방침

시행일: 2026년 10월 27일

울타리 제작자는 서버를 운영하지 않으며, 선생님이 직접 보낸 의견 외에는 선생님과 학생의 정보를 받거나 보관하지 않습니다. 울타리의 모든 자료는 선생님 본인의 구글 계정에 만들어진 Firebase 프로젝트에 저장됩니다.

1. 설치 프로그램이 요청하는 구글 계정 정보와 사용 목적

이메일 주소
openid email		설치한 계정을 울타리의 선생님 계정으로 지정하는 데 사용합니다. 이메일 주소는 선생님 프로젝트의 보안 규칙에만 기록됩니다.
Google Cloud 관리
cloud-platform		선생님 계정에 울타리용 프로젝트를 만들고, 저장소(Firestore)·로그인(Authentication)·보안 규칙을 설정하는 데 사용합니다.
Firebase 관리
firebase		프로젝트에 Firebase를 연결하고, 울타리 화면을 선생님의 주소(Hosting)에 올리는 데 사용합니다.

위 권한은 울타리 설치와 업데이트에만 사용합니다. 선생님의 다른 구글 서비스(메일, 드라이브 등)나 울타리와 관계없는 다른 프로젝트의 자료는 읽거나 바꾸지 않습니다.

2. 로그인 정보의 보관

  • 업데이트를 위해 구글이 발급한 로그인 토큰을 선생님 PC에만 저장합니다. 이 토큰은 구글 서버 외의 곳으로 보내지 않습니다.
  • 언제든지 구글 계정 › 보안 › 서드 파티 액세스에서 울타리의 권한을 해제할 수 있습니다. 해제하면 PC에 저장된 토큰은 더 이상 사용할 수 없습니다.

3. 울타리에 저장되는 자료

  • 학생 이름, 학생이 올린 글·사진·파일, 좋아요·댓글, 담벼락 설정이 선생님의 Firebase 프로젝트(서울 지역)에 저장됩니다.
  • 학생은 구글 계정 없이 이름만 입력해 참여하며, 학생 기기에는 익명 로그인 정보가 저장됩니다.
  • 자료의 관리 책임과 삭제 권한은 선생님에게 있습니다. 담벼락이나 글을 지우면 저장소에서도 삭제되며, Firebase 프로젝트를 삭제하면 모든 자료가 삭제됩니다.

4. 제3자 제공 및 외부 전송

  • 울타리 제작자는 선생님이 직접 보낸 의견(5항) 외에는 어떠한 정보도 수집하지 않으며, 제3자에게 제공하지 않고, 광고·분석 도구를 사용하지 않습니다.
  • 자료는 선생님이 사용하는 구글(Firebase)의 서비스 안에서만 처리됩니다. 구글의 처리 방식은 구글 개인정보처리방침을 따릅니다.
  • 새 버전 확인을 위해 선생님 화면이 공개 저장소(GitHub)의 버전 파일을 읽습니다. 이때 개인정보는 보내지 않습니다.

5. 의견 보내기

  • 선생님이 [의견 보내기]에서 보내기를 누를 때만, 아래 내용이 제작자의 의견 저장소로 전송됩니다.
  • 항상 보내는 것: 의견 종류, 선생님이 쓴 내용, 울타리 버전, 브라우저 종류, 화면 크기
  • 선택한 경우에만 보내는 것: 최근 사용 기록(학생 이름은 '학생1, 학생2'로 바꾸고 글·댓글 내용은 글자 수만 남기며, 이메일과 프로젝트 주소는 일부를 가립니다), 의견 보내기를 누른 순간의 울타리 화면 캡처
  • 보낼 기록과 캡처는 보내기 전에 선생님이 직접 확인할 수 있습니다. 화면에 학생 이름이나 사진이 보이면 캡처를 보내지 않도록 안내합니다.
  • 받은 의견은 오류 수정과 기능 개선에만 사용하며, 처리가 끝나면 삭제합니다.
  • 구글 계정 정보(로그인 토큰 등)는 의견과 함께 보내지 않습니다.

6. 구글 API 서비스 사용자 데이터 정책 준수

울타리가 구글 API로 받은 정보를 사용하고 다른 곳으로 옮기는 방식은 제한적 사용(Limited Use) 요구사항을 포함한 Google API 서비스 사용자 데이터 정책을 따릅니다.

Privacy Policy (English)

The developer of Wooltari operates no server and does not collect, receive, or store any personal data, except feedback that a teacher chooses to send. All Wooltari data is stored in a Firebase project created in the teacher's own Google account.

Google user data accessed. openid/email: to set the installing account as the teacher account in the project's security rules. cloud-platform: to create the Wooltari project in the teacher's account and enable Firestore, Authentication and security rules. firebase: to add Firebase to that project and deploy the app to Firebase Hosting. These permissions are used only to install and update Wooltari. The app does not access the teacher's Gmail, Drive, or any unrelated project.

Storage. The OAuth refresh token is stored only on the teacher's PC to perform updates and is never sent anywhere other than Google. Access can be revoked at any time at myaccount.google.com/permissions.

Sharing. Apart from feedback the teacher chooses to send, no data is shared with the developer, and no data is shared with any third party. No ads or analytics are used. The app checks a public version file on GitHub for updates without sending personal data.

Limited Use. Wooltari's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Feedback. Only when the teacher presses Send in the in-app feedback form, the following is sent to the developer's feedback store: feedback type, the teacher's message, app version, browser and screen size, and—only if the teacher opts in—a recent usage log (student names replaced with "Student 1, 2…", post and comment text reduced to character counts, emails and project IDs partly masked) and a screenshot of the Wooltari page. The teacher can review the log and screenshot before sending. No Google account data (such as OAuth tokens) is included. Feedback is used only to fix bugs and improve the app and is deleted after it is handled.
